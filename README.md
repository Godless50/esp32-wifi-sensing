# WSN — датчик присутствия по Wi-Fi на ESP32-S3

Платы ESP32-S3 измеряют радиоканал Wi-Fi (CSI) между собой и роутером. Человек, который ходит по квартире,
меняет этот канал. Сервер на вашем компьютере по этим изменениям определяет, в какой комнате движение, где
человек и есть ли кто-нибудь дома. Приложение на телефоне нужно для трёх вещей: разметить квартиру, записать
сценарий для обучения и смотреть карту.

```
 платы ESP32-S3 ──UDP──▶ сервер (Docker на вашем компьютере) ◀──HTTPS── приложение Android
  CSI от роутера          приём, модель квартиры, карта            разметка, сценарий, карта
  и друг от друга                       ▲
                               ./train.sh — обучение на записи сценария
```

## Что нужно

| | |
|---|---|
| Платы | 1–4 платы **ESP32-S3**. Лучше всего модули N16R8 (16 МБ флеша и PSRAM); подходят и платы с 8 МБ флеша без PSRAM. Нужен USB-кабель **с линиями данных**. Чем больше плат, тем точнее комнаты: удобно ставить по одной на 1–2 комнаты |
| Компьютер | **Linux** (Ubuntu, Debian, Fedora…, x86-64 или ARM64) с **Docker** и Docker Compose v2. Это сервер: он должен быть включён, пока система работает |
| Wi-Fi | Сеть **2,4 ГГц**: ESP32 не работает в 5 ГГц. Mesh-системы поддерживаются: каждая плата сама подключается к ближайшему узлу |
| Телефон | Android 8+ с поддержкой **ARCore** («Сервисы Google Play для AR»): по камере телефон знает, где он находится в квартире |

## Установка: три шага

### 1. Компьютер и платы: `./install.sh`

Подключите платы к компьютеру по USB, к разъёму «USB», а не «UART». Затем:

```bash
git clone https://github.com/Godless50/esp32-wifi-sensing.git
cd esp32-wifi-sensing
./install.sh
```

Скрипт делает по порядку:
1. Проверяет Docker и спрашивает пароль для приложения и веб-интерфейса (пользователь `wsn`).
2. Собирает и запускает сервер.
3. Находит платы и сам выбирает вариант прошивки по памяти каждой платы. Каждую прошивает только после вашего
   подтверждения: всё, что было на плате, стирается.
4. Показывает сети Wi-Fi, которые видит плата, спрашивает сеть и её пароль, записывает в платы адрес сервера.
5. Показывает два QR-кода: ссылку на приложение и код сопряжения телефона с сервером.

Повторный запуск безопасен: то, что уже сделано, скрипт пропускает. Потом платы можно отключить от компьютера и
расставить по квартире. Питание — от любого USB-зарядника, данные идут по Wi-Fi.

### 2. Телефон: разметка и сценарий

1. Установите приложение по QR-коду со ссылкой (или скачайте `wsn.apk` со страницы Releases). Откройте его,
   нажмите «Сопряжение (QR)» и наведите камеру на QR-код сопряжения. Введите пароль из шага 1.
2. «Разметка квартиры и запись сценария» → «Начать запись». **Пока идёт запись, в квартире должны быть только
   вы.**
3. **Устройства.** Поднесите телефон вплотную к каждой плате и к роутеру (или к узлам mesh, к которым
   подключены платы) и нажмите «Отметить». По этим отметкам строится план.
4. **Комнаты.** Введите имя комнаты и нажмите «Новая комната». Наводите кружок на стык пола и стены в каждом углу
   по кругу и нажимайте «Угол», затем «Закрыть комнату». В каждом дверном проёме нажмите «Дверь».
5. **Сценарий.** Телефон ведёт по шагам, всего около 15 минут:
   - выйти из квартиры;
   - в каждой комнате походить, постоять и посидеть;
   - пройти по всем комнатам;
   - снова выйти.
   В конце нажмите «Сохранить».

### 3. Обучение: `./train.sh`

```bash
./train.sh
```

Скрипт обучает модель вашей квартиры на записанном сценарии. Работает на всех ядрах процессора и занимает
несколько минут, в зависимости от мощности компьютера и длины записи. Перед сохранением модель честно проверяется
на кусках записи, которых она не видела, и скрипт печатает, как часто она узнаёт каждую комнату. Сервер подхватывает
новую модель сам.

**Готово.** В приложении откройте «Карту»: на ней видно, в каких комнатах движение, где человек и есть ли кто-нибудь
дома. Веб-интерфейс открывается по адресу `https://<адрес компьютера>:8443`.

## Расстановка плат

Как стоят платы, влияет на качество больше всего остального:
- **Ставьте платы в разные комнаты**, на высоте 0,5–1,5 м. Не ставьте их в металлические шкафы и за холодильник.
- Каждая плата измеряет линию «роутер → плата» и линии от других плат. Движение лучше всего видно на этих линиях
  и рядом с ними. Комнату, через которую не идёт ни одна линия, система различает хуже.
- **Если переставили плату, сменили роутер или передвинули мебель**, сделайте заново разметку и сценарий,
  затем `./train.sh`.

## Команды

| Команда | Что делает |
|---|---|
| `./install.sh` | Полная установка; повторный запуск безопасен |
| `./install.sh flash` | Прошить и настроить новые платы, подключённые по USB |
| `./install.sh wifi` | Только сменить Wi-Fi или адрес сервера у плат, без прошивки |
| `./install.sh pair` | Снова показать QR-код сопряжения |
| `./install.sh status` | Показать, что работает: платы, план, запись, модель |
| `./install.sh password` | Сменить пароль приложения |
| `./install.sh apk` | Собрать приложение из исходников (Docker, около 10 минут) |
| `./train.sh` | Обучить модель на новой записи |
| `./train.sh --check` | Только проверить качество, модель не менять |
| `./train.sh --rollback` | Вернуть прежнюю модель |

Ключ `--host IP` задаёт адрес компьютера вручную. Закрепите этот адрес за компьютером в настройках роутера
(DHCP reservation): платы отправляют данные именно на него.

## Как это устроено

- **Прошивка** (`firmware/`, ESP-IDF 5.4). Плата снимает CSI с кадров своей точки доступа. Частота около
  100 Гц, её задают зонды сервера. Каждая плата также рассылает маяки ESP-NOW; другие платы находят их сами,
  настраивать ничего не нужно. Данные идут по UDP с подписью HMAC. Новая прошивка ставится по воздуху с
  откатом: `tools/push_fw.sh`.
- **Сервер** (`server/`, Python, FastAPI) работает в Docker вместе с Caddy (HTTPS с собственным центром
  сертификации и пароль). Сервер принимает данные плат, строит план по отметкам телефона и запускает модель
  квартиры. Без модели он оценивает движение по геометрии линий.
- **Модель** (`server/wsn/zonemodel.py`, `server/wsn/train.py`). Для каждой линии берутся признаки движения
  за 4 секунды, отнесённые к тихому уровню этой же линии за последний час, — так фон радио меньше сбивает
  модель. Признаки обрабатывает ансамбль небольших нейросетей на numpy. Метки берутся из записи: где был
  телефон и с какой скоростью он двигался. Обучение и работа на сервере используют один и тот же код признаков.
- **Приложение** (`android/`, Kotlin, ARCore) отвечает за сопряжение по QR, разметку, сценарий и карту.

## Безопасность и данные

- **Пароль Wi-Fi** вводится один раз в `install.sh` и уходит только в память плат. На диск, в журналы и в
  командную строку он не попадает.
- **Пароль приложения** хранится только в виде хеша (`data/caddy.env`).
- **Сертификат сервера** выпускает его собственный центр сертификации. Приложение доверяет только ему: код из
  QR-кода — это SHA-256 корневого сертификата. В APK нет ничьих сертификатов, поэтому один APK подходит к любому
  серверу.
- **Все записи, план и модель** хранятся только у вас, в папке `data/`. В облако ничего не отправляется.

## Ограничения

- **Точно отслеживается один человек.** Если людей несколько, система показывает нижнюю оценку их числа и
  комнаты с движением.
- **Неподвижного человека видно плохо.** Дыхание заметно, только если человек рядом с линией. Если после
  движения стало тихо, считается, что человек остался там, где остановился.
- **Установка работает только на Linux**: доступ Docker к USB. Под Windows возможен вариант WSL2 + usbipd, но
  он не проверен.
- **Страна Wi-Fi в прошивке — RU** (каналы 1–13): для России и Европы это подходит.

## Разработка

```bash
docker compose -f deploy/docker-compose.yml build api
docker run --rm -v $PWD/server:/app -v $PWD/tools:/tools:ro -v $PWD/firmware:/firmware:ro -w /app wsn-server python -m pytest -q
tools/android_build.sh test        # тесты приложения
tools/fw.sh build                  # прошивка (Docker с ESP-IDF)
tools/release_fw.sh                # образы для install.sh: firmware/dist
tools/android_build.sh release     # wsn.apk (ключ подписи создаётся в ~/.config/wsn)
```

Исследовательская история проекта — эксперименты с моделями, замеры и диагностика плат — хранится в ветке
`phase2-capture-3d`.
