# Wi-Fi Sensing — дополнения v2 по проверке источников (2026-10-14)

Основание: проверка концепта «Micro-Jev-CSI» по первоисточникам (ESP-IDF, esp-csi, ESP-NN, ESP-DL, статьи
по CSI-сенсингу и калибровке). Документ не заменяет `2026-10-12-wifi-sensing-design.md`, а фиксирует, что из
проверки принято в этот проект, что уже было сделано, что отложено и почему. Правило: вывод о поведении плат —
только по числам с устройства, с привязкой к сборке, против записанной базы.

## 1. Что уже совпадало с проверенной практикой (не трогаем)

| Пункт v2 | В проекте | Где |
|---|---|---|

| Жёсткий BSSID, без роуминга | locked BSSID, откат на любой узел после 5 неудач | `wifi_mgr.c` |

## 2. Принято сейчас (этот коммит)

1. **Измерительный канал** `tools/link_metrics.py` + второй mirror-сокет API (`data/run/measure.sock`):
   по каждой плате и линку — частота, интервалы между кадрами по часам платы p50/p95/p99/max, провалы > 50/200/1000 мс,
   потери датаграмм по `seq`, время инференса на плате p50/p95/p99, минимум свободной кучи, версии прошивки и модели.
   Результат — JSON в `data/eval/` с git SHA репозитория. Живой learner (`csi.sock`) не затрагивается.
2. **Рабочая и отладочная прошивки разделены.** Полная проверка кучи (`HEAP_POISONING_COMPREHENSIVE`), которой
   13.10 искали порчу памяти, искажает замеры скорости. Рабочий профиль — `HEAP_POISONING_LIGHT` (метки на границах
   блоков остаются, `guard_heap_check()` по-прежнему ловит переполнение), отладочный — `sdkconfig.debug`
   (`tools/fw.sh build-debug`). Конфиг рабочей сборки теперь всегда собирается из `sdkconfig.defaults` (воспроизводимо
   из git); проверено: от прежнего ручного `sdkconfig` он отличается ровно одной строкой — уровнем проверки кучи.
   `tools/push_fw.sh` пишет `data/ml/fw_<id>.json` (id образа → git SHA, профиль).
3. **Калибровка вероятностей** (`ml/calib.py`: Brier, ECE, NLL, температура). Learner:
   - гейт отклоняет дообучение, если ECE на отложенных размеченных сессиях растёт больше `--ece-tol` (0.02) по любой голове;
   - вероятности, отправляемые в UI, проходят через температуру по головам; она пересчитывается для каждой принятой модели
     и хранится в `meta.json` (`temperature`);
   - `ml/calib_eval.py` — отчёт с перекрёстной проверкой температуры (подбор на одной сессии, проверка на другой).
4. **Слабые метки Home Assistant** (`tools/ha_labels.py` → `data/labels/ha.jsonl`, `ml/ha_weak.py`): «дома никого
   ≥ 10 мин» по `person.*` — учитель, не зависящий от радио. Гейт learner: на таких живых окнах доля «есть движение»
   у новой модели не выше старой + `--tol` (нужно ≥ `--min-ha` окон). Без токена HA гейт не включается.

## 3. Отложено (с причиной)

| Пункт v2 | Почему не сейчас | Условие, при котором делать |
|---|---|---|
| Полоса 10–45 Гц для резких событий (падение) | признаки платы — корзины 0.1 с (до 5 Гц); нужны новые признаки, данные с падениями и переобучение | есть размеченные резкие события; частота основного линка ≥ 95 Гц с p99 интервала ≤ 30 мс (замер) |
| ESP-DL вместо TFLM | TFLM+ESP-NN уже работает; смена фреймворка без замера выигрыша — риск | замер: доля времени нейросети в `infer_ms` (по этапам) > 30 % |
| Self-attention на плате | паритет компактного Transformer на ESP-DL в публикации 75/100 | не планируется |
| Компенсация усиления через `esp-csi-gain-ctrl` | сейчас — программная нормировка АРУ; замена меняет признаки и ломает обученные модели | новая версия признаков с переобучением |
| Обещание точного числа людей / координат | на одном линке по литературе недостижимо cross-domain | — |

## 4. Найдено при проверке (не исправлено в этом коммите)

- **Отложенные сессии не отложены для базовой модели.** `VAL_SESSIONS` learner (`053501-ee64`, `065019-45cd`) входят в
  `trained_on` модели `live_model_s2`. Онлайн-дообучение их не подмешивает, но базовая модель на них обучалась: оценки гейта
  и калибровки на них — по обучающим данным, оптимистичны. Нужна новая размеченная сессия, которая не входит в обучение.
- На этих (обучающих) сессиях модель выглядит недоуверенной (T < 1). **На сессиях, которых она не видела, — наоборот:**
  сильно самоуверенна и в основном ошибается (п. 5.3). Температура, подобранная на обучающих сессиях, ухудшала бы
  ответы, поэтому learner подбирает её только по размеченным сессиям вне `trained_on`, а без них оставляет T = 1.

### 5.3 Калибровка на сессиях, не входивших в обучение (честная оценка)

`data/eval/calib-1791892839-heldout.json`, набор `data/ml/heldout_v1.npz` (`build_seq.py`): сессии

| Голова | n | точность | Brier | ECE | T (по всем) |
|---|---|---|---|---|---|
| активность (4 класса) | 84 | 0.369 | 0.782 | 0.330 | 6.0 |
| «есть движение» | 1303 | 0.330 | 0.972 | 0.453 | 8.0 (предел сетки) |

В окнах, где по разметке никто не двигался, модель говорила «движение» примерно в 2/3 случаев. Температура, подобранная
на двух других сессиях, на третьей снижает ECE головы движения 0.546 → 0.307 и 0.380 → 0.200, но точность от неё не
меняется. Вывод: оценки гейта learner на `VAL_SESSIONS` к новым записям не переносятся; нужна новая размеченная
запись вне обучения (лучше — несколько, с моментами «пусто» и «тихо сижу»).
